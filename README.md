# Видеовстречи с залом ожидания и показом записей

Сервис видеоконференций в стиле Zoom: участники заходят по ссылке, организатор управляет всем из админ-панели.

## Возможности

- **Зал ожидания:** участник попадает во встречу только после того, как организатор нажмёт «Впустить». Можно впустить всех разом, отклонить или закрыть встречу для новых.
- **Права на камеру и микрофон:** общие для встречи и отдельно для каждого участника. Есть кнопки «всем выключить микрофон / камеру», «опустить руки», «удалить из встречи».
- **Управление прямо во встрече:** у ведущего во встрече есть панель «Управление» с теми же переключателями доступа, запуском и паузой записи, ссылкой и кнопкой «завершить для всех».
- **Показ записи:**
  - загрузите видео или запишите его в «Студии записи»;
  - видео показывается как камера ведущего (плитка с вашим именем) или как демонстрация экрана, звук идёт из видео;
  - запуск вручную, по расписанию или через N секунд после входа первого участника;
  - **повтор:** каждый день, по будням или каждую неделю. Ссылка остаётся той же, запись и настройки те же, чат очищается перед каждым повтором;
  - видео синхронно у всех, опоздавшие попадают в текущий момент.
- **Запись ведущего во встрече:** кнопка «Запись» у ведущего пишет только его микрофон и то, что он показывает (камеру, демонстрацию экрана или экран с камерой в углу). Участники, их звук и видео в запись не попадают. После «Стоп» запись сама сохраняется в «Записи» и её можно показывать на других встречах.
- **Настройки по умолчанию:** с ними создаётся каждая новая встреча (доступ, запись, имя ведущего, расписание). Встречу можно **дублировать** со всеми настройками.
- **Несколько админов:** главный админ (пароль из `ADMIN_PASSWORD`, логин `admin`) создаёт других в разделе «Админы». У каждого свои встречи, записи, эмодзи и настройки — чужое не видно.
- **Невидимый вход:** только из админки (кнопка с перечёркнутым глазом). Участники такого наблюдателя не видят.
- **Эмодзи:** Apple-эмодзи в реакциях и чате, нарисованный набор стикеров (`:fire:`, `:top:`, `:thanks:`…) и свои картинки каждого админа.
- **Проверка микрофона и выбор устройств:** индикатор громкости перед входом, выбор микрофона, камеры и динамиков, понятные подсказки, если браузер не дал доступ.

## Запуск на Windows (проще всего)

1. Скачайте проект: на GitHub нажмите **Code → Download ZIP** и распакуйте архив в любую папку, например `C:\Conference`.
2. Дважды щёлкните **`start.bat`**. При первом запуске он:
   - установит Node.js, если его нет (через winget; после установки запустите `start.bat` ещё раз);
   - установит зависимости;
   - спросит пароль для админ-панели и сохранит его в `admin-password.txt`;
   - создаст ярлык **Conference** на рабочем столе.
3. Откроется браузер с админ-панелью. Сервер работает, пока открыто чёрное окно; закройте окно, и сервер остановится.

Дальше запускайте сервер ярлыком с рабочего стола. Чтобы сменить пароль, удалите `admin-password.txt`.

## Запуск вручную (Windows, Mac, Linux)

Нужен Node.js 18 или новее.

```bash
npm install
ADMIN_PASSWORD='ваш-надёжный-пароль' npm start
```

- Сайт для участников: `http://localhost:3000`, ссылки на встречи выглядят как `/r/abc-defg-hij`
- Админ-панель: `http://localhost:3000/admin`

### Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `ADMIN_PASSWORD` | пароль главного администратора | `admin` (**обязательно поменяйте**) |
| `ADMIN_LOGIN` | логин главного администратора | `admin` |
| `PORT` | порт | `3000` |
| `DATA_DIR` | где хранить базу и загруженные файлы | `./data` |
| `MAX_UPLOAD_MB` | максимальный размер видео | `4096` |
| `TURN_URL`, `TURN_USER`, `TURN_PASS` | TURN-сервер, если участники не видят друг друга | — |

## Установка на сервер Ubuntu 24.04 одной командой

```bash
curl -fsSL https://raw.githubusercontent.com/konstahasan-cyber/conference-/claude/video-conference-recording-service-4y8f5m/deploy/install.sh -o install.sh
sudo bash install.sh
```

Скрипт спросит домен (если домена нет, нажмите Enter: будет бесплатный адрес вида `1-2-3-4.sslip.io`) и пароль админки. Затем он поставит Node.js, ffmpeg, Caddy с автоматическим HTTPS, TURN-сервер coturn, настроит автозапуск и файрвол. Повторный запуск `sudo bash /opt/conference/deploy/install.sh` обновляет код и сохраняет настройки и данные.

### Быстрые команды на сервере

```bash
video-update      # обновить до последней версии (код приложения; Caddy и другие проекты не трогаются)
video restart     # перезапустить
video logs        # логи
video url         # адрес сайта и админки
video password    # сменить пароль админки
video help        # все команды
```

## Размещение в интернете вручную

1. **Нужен HTTPS**: без него браузеры не дают доступ к камере и микрофону (кроме `localhost`). Проще всего поставить перед сервисом Caddy:
   ```
   meet.example.com {
       reverse_proxy localhost:3000
   }
   ```
   С nginx не забудьте пробросить WebSocket (`Upgrade`/`Connection`) и увеличить `client_max_body_size` для загрузки видео.
2. **TURN-сервер** (например, coturn) нужен, чтобы видео участников проходило через строгие NAT и корпоративные сети. Укажите его в `TURN_URL=turn:turn.example.com:3478` и задайте `TURN_USER`/`TURN_PASS`.
3. **ffmpeg** (по желанию, ставится скриптом установки). Загруженные и записанные видео приводятся к MP4 (H.264 + AAC): подходящие файлы только пересобираются, остальные (WebM из браузера) перекодируются в фоне с низким приоритетом. Так записи играют везде, включая iPhone, а опоздавшие мгновенно попадают в нужный момент.

## Что важно знать

- Видео участников передаётся напрямую между браузерами (mesh). Это хорошо работает примерно до 8–10 человек с включёнными камерами. Если смотрят в основном запись, а камеры у участников выключены, людей может быть заметно больше: запись каждый скачивает с сервера, поэтому нужен хороший исходящий канал у сервера.
- Для записи лучше всего подходит MP4 (H.264 + AAC): он воспроизводится во всех браузерах, включая Safari и iPhone.
- Если браузер заблокировал автозапуск со звуком, участник увидит кнопку «Нажмите, чтобы включить звук».
- Данные хранятся в `data/db.json`, файлы — в `data/uploads/`, кэш Apple-эмодзи — в `data/cache/`.
- Apple-эмодзи сервер один раз скачивает с jsdelivr (пакет `emoji-datasource-apple`) и дальше отдаёт сам. Это изображения Apple: для личного использования нормально, для коммерческого продукта лучше заменить на свободный набор (Twemoji, Noto).
- Иконки интерфейса — [Lucide](https://lucide.dev) (лицензия ISC, `public/icons/LICENSE.txt`).
