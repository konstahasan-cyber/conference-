# Zoom-пульт (zoom-runner)

Небольшая программа на Node.js 22, которая сама показывает заранее записанный эфир («автовебинар») в Zoom-встрече.
Работает на Windows Server в сеансе пользователя (RDP), рядом с сервером конференций.

Как это устроено:

- сервер конференций говорит, какую запись, с какого места и в какую Zoom-встречу показывать
  (`/api/zoom/poll`, раз в 2 секунды);
- **OBS Studio** открывает файл записи в сцене «Автовебинар» и отдаёт картинку через встроенную
  **виртуальную камеру OBS**, а звук — через мониторинг на виртуальное устройство **VB-CABLE** («CABLE Input»);
- **Zoom** видит запись как камеру «OBS Virtual Camera» и микрофон «CABLE Output»;
- в Zoom пульт заходит по официальной ссылке `zoommtg://zoom.us/join?...`, управляет OBS через встроенный
  сервер obs-websocket;
- пауза, продолжение и перемотка в админке конференции повторяются в OBS; каждые 10 с пульт сверяет позицию
  и поправляет, если запись «уплыла» больше чем на 2 с;
- когда эфир закончился — запись в OBS останавливается, а через 5 с пульт выходит из Zoom (закрывает клиент Zoom);
- о своём состоянии пульт сообщает серверу (`/api/zoom/report`), его видно в админке встречи.

Если в задании включён тестовый режим (`noJoin`), всё делается в OBS, но в Zoom пульт не заходит и Zoom не закрывает.

Сторонних npm-пакетов нет, нужен только Node.js 22.

## Однократная настройка

Всё делается один раз под тем пользователем Windows, в сеансе которого будет работать пульт.

### 1. VB-CABLE

1. Скачайте VB-CABLE Driver с сайта vb-audio.com, распакуйте и запустите `VBCABLE_Setup_x64.exe` от имени администратора → Install Driver.
2. Перезагрузите сервер.
3. В «Звук» Windows должны появиться «CABLE Input» (воспроизведение) и «CABLE Output» (запись).
   Не делайте CABLE Input устройством по умолчанию.

На Windows Server может понадобиться включить службу «Windows Audio» (Audiosrv) и поставить ей автоматический запуск.

### 2. OBS Studio (версии 28 или новее)

1. Установите OBS в папку по умолчанию (`C:\Program Files\obs-studio`). При первом запуске мастер настройки можно пропустить.
2. **Инструменты → Настройки сервера WebSocket**: включите «Включить сервер WebSocket», порт 4455,
   включите аутентификацию и скопируйте пароль в `obsPassword` в файле настроек пульта.
3. **Настройки → Аудио → Дополнительно → Устройство мониторинга**: выберите **«CABLE Input (VB-Audio Virtual Cable)»**.
   Без этого в Zoom не будет звука (пульт предупредит об этом в админке).
4. **Настройки → Видео**: базовое разрешение 1920×1080 (или 1280×720), 30 FPS.
5. Сцену «Автовебинар» и источник «Запись» пульт создаст сам. Ничего в них руками менять не нужно.
6. Один раз нажмите «Запустить виртуальную камеру», чтобы убедиться, что она работает, и закройте OBS —
   дальше пульт сам запускает OBS и камеру.

### 3. Zoom (клиент для Windows)

1. Установите клиент Zoom и войдите в аккаунт, от имени которого будет вестись автовебинар
   (лучше — аккаунт организатора встречи). Отметьте «Не выходить из системы».
2. **Настройки → Видео**: камера **OBS Virtual Camera**, включите «Включать моё видео при подключении к конференции»
   (или выключите «Выключать моё видео…» — название зависит от версии), выключите «Отражать моё видео»
   и «Подправить мой внешний вид».
3. **Настройки → Звук**: микрофон **CABLE Output (VB-Audio Virtual Cable)**, динамик — любой, кроме CABLE Input.
   Выключите «Автоматически регулировать громкость микрофона», шумоподавление поставьте «Низкое»
   (иначе Zoom «режет» музыку и голос в записи). Включите «Автоматически подключать звук с компьютера при входе в конференцию»
   и выключите «Выключать мой микрофон при входе в конференцию».
4. **Настройки → Общие**: выключите «Спрашивать подтверждение при выходе из конференции» (если есть).
5. Проверьте вручную: зайдите в любую свою встречу по ссылке — сразу должно быть видно картинку OBS и слышен звук.

### 4. Пульт

1. Скопируйте папку `zoom-runner` на сервер, например в `C:\conference\zoom-runner`.
2. Скопируйте `config.example.json` в `C:\conference\zoom-runner.json` и заполните:

   | Поле | Что это |
   |---|---|
   | `server` | адрес сервера конференций, обычно `http://127.0.0.1:3000` |
   | `tokenFile` | файл с токеном пульта; сервер создаёт его сам в папке данных (`data\zoom-runner.token`) |
   | `obsUrl`, `obsPassword` | адрес и пароль сервера WebSocket в OBS |
   | `obsExe` | путь к `obs64.exe` — чтобы пульт мог сам запустить OBS |
   | `zoomExe` | обычно `null` (ссылка открывается через Windows). Можно указать путь к `Zoom.exe` — тогда ссылка передаётся ему через `--url=` |
   | `leaveOnEnd` | `true` — выходить из Zoom (закрывать клиент) после конца эфира |
   | `sceneName`, `inputName` | имена сцены и медиаисточника в OBS |
   | `joinRetrySec` | необязательно: через сколько секунд повторять вход в Zoom, если он не удался (по умолчанию 60) |

3. Запуск вручную: `start-zoom-runner.bat` (или `node runner.js C:\conference\zoom-runner.json`).
4. Автозапуск: Планировщик заданий → «Создать задачу» → триггер «При входе в систему» (этого пользователя),
   действие — `C:\conference\zoom-runner\start-zoom-runner.bat`, «Выполнять только для пользователей, вошедших в систему».
   Пульт **должен** работать в интерактивном сеансе пользователя (не как служба), иначе Zoom и OBS не откроются.

### Про RDP

Zoom и OBS работают, только пока сеанс пользователя существует. Не нажимайте «Выйти» (log off) —
просто закрывайте окно RDP. Если после отключения RDP картинка в Zoom замирает, отключайтесь командой
(от администратора, в самом сеансе): `tscon %sessionname% /dest:console` — сеанс останется активным на «консоли».
Нужно, чтобы Windows не блокировала сеанс и не засыпала: схема питания «Высокая производительность», заставка выключена.

## Как проверить, что всё работает

- В админке встречи с включённым Zoom виден статус пульта: состояние, текущий шаг или ошибка, подключён ли OBS,
  включена ли виртуальная камера, во встрече ли Zoom, позиция записи.
- Журнал пульта: `C:\conference\logs\zoom-runner.log` (папка `logs` рядом с файлом настроек).
  При размере больше 10 МБ старый журнал переименовывается в `zoom-runner.log.1`.
- Журнал сервера: строки `ZOOM <состояние>: <сообщение>`.

Частые сообщения:

| Сообщение | Что сделать |
|---|---|
| «неверный пароль obs-websocket» | исправить `obsPassword` |
| «OBS не отвечает по WebSocket» | в OBS включить сервер WebSocket, проверить порт |
| «В OBS не выбран мониторинг «CABLE Input»» | шаг 2.3 выше |
| «не удалось включить виртуальную камеру OBS» | переустановить OBS, проверить, что виртуальная камера запускается вручную |
| «Zoom не заходит во встречу» | открыть Zoom на сервере, проверить вход в аккаунт, нет ли окна с вопросом (пароль, зал ожидания, «Подключить звук») |
| «файл записи не найден на этом компьютере» | пульт и сервер должны работать на одной машине (или путь к записям должен быть одинаковым) |
| «Сервер … недоступен» / «Сервер отклонил токен (401)» | запущен ли сервер; тот ли `tokenFile` |

## Файлы

- `runner.js` — основная программа (цикл раз в 2 с);
- `obs.js` — маленький клиент obs-websocket v5;
- `platform.js` — действия Windows (открыть ссылку, проверить процессы `Zoom.exe`/`CptHost.exe`, закрыть Zoom, запустить OBS).
  С `ZOOM_RUNNER_FAKE_PLATFORM=1` вместо них только пишет в консоль — для проверки на Linux;
- `zoomlink.js` — разбор ссылки Zoom (`https://…zoom.us/j/<номер>?pwd=…`, `/s/…`, `zoommtg://…`, «номер», «номер пароль»);
- `config.example.json` — образец настроек;
- `start-zoom-runner.bat` — запуск с автоматическим перезапуском.
